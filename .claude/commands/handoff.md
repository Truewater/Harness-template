컨텍스트를 비우기(`/clear`) 전에 인수인계 문서를 작성하라. 새 세션은 이 대화를 전혀 모른다는 전제로 쓴다.

## 절차

1. 지금 진행 중인 수정이 반쯤 된 상태라면, 가장 가까운 안정 지점(테스트 통과)까지만 마무리한다. 새 작업은 시작하지 마라.
2. CLAUDE.md "명령어" 섹션의 테스트 명령을 직접 실행해 결과를 확인한다.
3. `git status --short --branch`, `git diff --stat`으로 현재 상태를 확인한다.
4. `date +%Y%m%d-%H%M`으로 시각을 얻어 `.omc/handoffs/{시각}-{주제-kebab-case}.md`에 아래 형식으로 저장한다.
5. 저장한 파일 경로를 알려주고, 사용자에게 `/clear` 후 `/resume`을 실행하라고 안내한다.

## 문서 형식

```markdown
# Handoff: {주제}

## 목표
(이 작업이 최종적으로 달성하려는 것, 1~2줄)

## 완료한 것
- (파일 경로와 함께)

## 현재 상태
- 브랜치:
- 커밋 안 된 변경:
- 테스트 결과: (직접 실행한 결과. 실패가 있으면 테스트 이름과 에러 요지)

## 결정 사항과 이유
- (버린 대안과 버린 이유 포함. 새 세션이 같은 시도를 반복하지 않게)

## 읽어야 할 파일
- (다음 작업에 꼭 필요한 파일만. 5개 이내를 목표로)

## 다음에 할 일
1. (바로 실행할 수 있는 수준으로. 첫 항목은 파일/함수 단위로 구체적으로)

## 주의 / 미해결
- 
```

## 금지사항

- 대화 내용을 그대로 옮겨 적지 마라. 이유: 문서가 길어지면 새 세션이 시작부터 컨텍스트를 낭비한다.
- git이 이미 기록하는 코드 diff를 문서에 붙여넣지 마라. 이유: `git diff`로 볼 수 있다. 문서에는 git에 남지 않는 "왜"와 "다음"을 적는다.
- 테스트를 실행하지 않고 결과를 추측해 적지 마라.
