이 프로젝트의 변경 사항을 리뷰하라.

먼저 다음 문서들을 읽어라:
- `CLAUDE.md`
- `docs/ARCHITECTURE.md`
- `docs/ADR.md`
- `docs/UI_GUIDE.md` (있을 때만. 없으면 6번 항목은 "해당 없음")

## 리뷰 대상

- 인자가 있으면 그 대상(브랜치, 커밋 범위, 파일)을 리뷰한다: $ARGUMENTS
- 없으면 `git diff main...HEAD`와 커밋 안 된 변경(`git status`, `git diff`)을 리뷰한다.

## 체크리스트

1. **아키텍처 준수**: ARCHITECTURE.md에 정의된 디렉토리 구조를 따르고 있는가?
2. **기술 스택 준수**: ADR에 정의된 기술 선택을 벗어나지 않았는가?
3. **테스트 존재**: 새로운 기능에 대한 테스트가 작성되어 있는가? 테스트가 외부 API를 mock하는가?
4. **CRITICAL 규칙**: CLAUDE.md의 CRITICAL 규칙을 위반하지 않았는가? 가능한 규칙은 grep 등으로 기계적으로 확인하고 명령과 결과를 근거로 남겨라.
5. **빌드 가능**: CLAUDE.md "명령어" 섹션의 lint·build·test를 **직접 실행**하고 결과를 적어라. 실행하지 않고 ✅를 주지 마라.
6. **UI 가이드 준수**: UI 변경이 있으면 UI_GUIDE.md를 기준으로 확인한다.
   - 안티패턴 표의 "검사 패턴"을 변경된 UI 파일에 grep으로 실행하고 명령과 결과를 남겨라. "수동 확인" 항목은 diff를 직접 읽어 판단하라.
   - 디자인 원칙(Primary 동작 하나, 파괴적 동작 분리, 간격 스케일, 접근성, 로딩/빈/에러 상태)을 diff 기준으로 확인하라.
   - 색상·타이포그래피 표에 정의된 값 밖의 임의 값(하드코딩된 hex, 임의 font-size 등)이 들어왔는지 확인하라.

## 출력 형식

| 항목 | 결과 | 비고 |
|------|------|------|
| 아키텍처 준수 | ✅/❌ | {상세} |
| 기술 스택 준수 | ✅/❌ | {상세} |
| 테스트 존재 | ✅/❌ | {상세} |
| CRITICAL 규칙 | ✅/❌ | {확인 명령과 결과} |
| 빌드 가능 | ✅/❌ | {실행한 명령과 결과} |
| UI 가이드 준수 | ✅/❌/해당 없음 | {grep 명령과 결과, 위반 항목} |

위반 사항이 있으면 수정 방안을 구체적으로 제시하라.
